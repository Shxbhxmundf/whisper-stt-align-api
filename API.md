# API Reference — whisper-stt-align-api

Base URL: `http://<SERVER_IP>:8888` (or `http://localhost:8888` through an SSH tunnel).

Interactive docs are auto-generated by FastAPI — open **`http://<SERVER_IP>:8888/docs`** in a browser to try every endpoint from a UI (or `/redoc` for reference-style docs).

All uploads are `multipart/form-data`. Audio can be anything ffmpeg decodes (wav, mp3, m4a, ogg...); everything is resampled to 16 kHz mono internally. Upload cap: 500 MB.

**Rule of thumb:** clips ≤ 5 min → sync endpoints (`/transcribe`, `/align`). Anything longer → jobs API (`/jobs/...`), submit then poll. Sync endpoints reject long audio with a 422 pointing you to the jobs API.

---

## The word object (returned everywhere)

```json
{ "word": "padhenge", "start": 2.84, "end": 3.31, "score": 0.91, "aligned": true }
```

| field | meaning |
|---|---|
| `start` / `end` | seconds, 3 decimal places, monotonically non-decreasing across the list |
| `score` | wav2vec2 alignment confidence 0–1 |
| `aligned` | `false` = word couldn't be aligned directly (digit, punctuation, mismatched region); its times are interpolated from neighbors and `score` is 0.0. Words are **never dropped**. |

```bash
curl -s http://<IP>:8888/health
```

```json
{
  "status": "ok", "gpu": "NVIDIA L40S", "cuda": true,
  "whisper_model": "large-v3",
  "align_models_loaded": ["en", "hi"],
  "busy": false,
  "jobs": {"queued": 0, "running": 0}
}
```

`busy: true` while a transcription/alignment is on the GPU. Health always responds, even mid-job.

## POST /transcribe — speech-to-text (sync, ≤ 5 min audio)

| form field | required | default | notes |
|---|---|---|---|
| `file` | yes | — | audio file |
| `language` | no | auto-detect | Whisper code: `hi`, `en`, ... |
| `align` | no | `true` | `false` = skip the word-timestamp pass (faster, segment-level only) |

```bash
curl -s -F "file=@clip.wav" http://<IP>:8888/transcribe | python3 -m json.tool
curl -s -F "file=@clip.wav" -F "language=hi" -F "align=false" http://<IP>:8888/transcribe
```

Response:

```json
{
  "text": "aaj hum Newton ke laws padhenge",
  "language": "en",
  "duration": 7.42,
  "model": "large-v3",
  "segments": [
    {"id": 0, "start": 0.11, "end": 3.9, "text": "aaj hum Newton ke laws padhenge",
     "words": [ ...word objects... ]}
  ],
  "words": [ ...all word objects, flattened... ],
  "warnings": []
}
```

With `align=false` the `words` arrays are empty (segment times only).

## POST /align — forced alignment of a known transcript (sync, ≤ 5 min audio)

Use when you already know the exact text that was spoken (TTS input, lecture script) and want per-word timings — more accurate than reading timestamps off `/transcribe`.

| form field | required | default | notes |
|---|---|---|---|
| `file` | yes | — | audio file |
| `transcript` | yes | — | the ground-truth text |
| `language` | no | auto by script | `en` = Latin/romanized-Hinglish text, `hi` = Devanagari. Auto-detect: any Devanagari char → `hi`, else `en`. |
| `mode` | no | `auto` | `single` / `chunked` / `auto` (auto switches to chunked above 300s) |

```bash
# Hinglish in Latin script -> en align model
curl -s -F "file=@tts_out.wav" \
     -F "transcript=aaj hum Newton ke laws padhenge" \
     http://<IP>:8888/align | python3 -m json.tool

# Devanagari -> hi align model, automatically
curl -s -F "file=@tts_out.wav" -F "transcript=आज हम पढ़ेंगे" http://<IP>:8888/align
```

Response:

```json
{
  "language": "en",
  "language_source": "auto_script_detect",
  "duration": 7.42,
  "mode": "single",
  "words": [ ...exactly one word object per whitespace token of transcript... ],
  "n_words": 6,
  "n_aligned": 6,
  "warnings": []
}
```

Chunked responses (long audio via jobs) additionally carry `"anchor_coverage": 0.0–1.0` — how much of your transcript was confidently matched to the audio. Below 0.15 the transcript probably doesn't belong to this audio; all words come back `aligned: false` with a warning.

## Jobs API — long audio (up to ~2h 10m)

### POST /jobs/transcribe and POST /jobs/align

Same form fields as their sync counterparts. Returns immediately:

```bash
curl -s -F "file=@lecture.mp3" http://<IP>:8888/jobs/transcribe
curl -s -F "file=@lecture.mp3" -F "transcript=$(cat script.txt)" http://<IP>:8888/jobs/align
```

```json
{"job_id": "a1b2c3d4e5f6", "status": "queued", "queue_position": 1, "poll": "/jobs/a1b2c3d4e5f6"}
```

### GET /jobs/{job_id}

```bash
curl -s "http://<IP>:8888/jobs/a1b2c3d4e5f6?include_result=false"   # cheap status poll
curl -s  http://<IP>:8888/jobs/a1b2c3d4e5f6                          # result embedded when done
```

```json
{
  "job_id": "a1b2c3d4e5f6", "task": "align",
  "status": "running",
  "stage": "aligning window 37/120", "progress": 0.57,
  "audio_duration": 7130.4, "error": null,
  "created_at": 1785155000.1, "started_at": 1785155002.9, "finished_at": null
}
```

- `status`: `queued → running → done | failed | cancelled`
- `stage` while running: `transcribing` → (align jobs) `anchoring` → `aligning window i/N` → `postprocessing`
- while `queued`, a `queue_position` field is included (1 = next)
- when `done`, a `result` field holds the exact same JSON the sync endpoint would return
- a 2h file takes roughly 6–12 min; poll every 5–15 s

Polling loop:

```bash
JOB=a1b2c3d4e5f6
while :; do
  S=$(curl -s "http://<IP>:8888/jobs/$JOB?include_result=false")
  echo "$S" | python3 -c "import sys,json;d=json.load(sys.stdin);print(d['status'],d['stage'],d['progress'])"
  echo "$S" | grep -qE '"status":"(done|failed|cancelled)"' && break
  sleep 10
done
curl -s http://<IP>:8888/jobs/$JOB > result.json
```

Python:

```python
import requests, time
BASE = "http://<IP>:8888"

with open("lecture.mp3", "rb") as f:
    job = requests.post(f"{BASE}/jobs/align", files={"file": f},
                        data={"transcript": open("script.txt").read()}).json()

while True:
    s = requests.get(f"{BASE}/jobs/{job['job_id']}", params={"include_result": "false"}).json()
    print(s["status"], s["stage"], s["progress"])
    if s["status"] in ("done", "failed", "cancelled"):
        break
    time.sleep(10)

result = requests.get(f"{BASE}/jobs/{job['job_id']}").json()["result"]
for w in result["words"][:20]:
    print(f"{w['start']:8.2f} {w['end']:8.2f}  {w['word']}")
```

### GET /jobs

Recent jobs (default 50, `?limit=` up to 200):

```bash
curl -s "http://<IP>:8888/jobs?limit=20"
```

### DELETE /jobs/{job_id}

```bash
curl -s -X DELETE http://<IP>:8888/jobs/a1b2c3d4e5f6
```

- job `queued` → cancelled
- job `running` → **409** (a running GPU job can't be killed safely)
- job finished → record + files deleted

Results are auto-purged 72h after job creation (`JOB_TTL_HOURS`) — fetch and store them. Uploaded audio is deleted as soon as the job finishes.

## Errors

Standard FastAPI shape: `{"detail": "<message>"}`.

| code | when |
|---|---|
| 400 | missing/empty/undecodable audio |
| 404 | unknown job id |
| 409 | DELETE on a running job |
| 413 | upload larger than 500 MB |
| 422 | empty transcript; unknown `language`/`mode`; audio too long for the sync endpoints (message tells you to use /jobs); `mode=single` on audio past the ~7 min OOM wall |
| 500 | inference crashed (full traceback in the server log — `tmux attach -t whisper_api`) |

## Notes

- Requests are processed one at a time on the GPU (FIFO). Concurrent sync requests queue on a lock; a long job delays everything behind it — check `queue_position`.
- No authentication. Keep port 8888 firewalled to your own IPs or use an SSH tunnel.
- Responses are gzip-compressed when the client sends `Accept-Encoding: gzip` (curl and requests do by default) — a 2h word-level result is a few MB uncompressed.
